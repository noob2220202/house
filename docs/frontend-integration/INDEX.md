# Frontend ↔ backend integration index

The one list the backend integrator works through. It merges every per-group note in this folder
(`foundation`, `consistency`, `w-*` user site, `a-*` broker console, `m-*` admin). The group notes
stay as the detailed reference (full payload shapes, mock behaviour, UI rationale); this file lists
**what has to be reconciled** and points to the section that has the details.

> **Status (2026-11-24, after integration stages 1–2):** `apps/api` now has the feature controllers
> and the frontends call the real API (mock mode remains for UI work). Owner decisions are in
> [`DECISIONS.md`](./DECISIONS.md) and win over this file; the work-item status is at the top of
> [`INTEGRATION_PLAN.md`](./INTEGRATION_PLAN.md). Items below that were settled are marked
> **Resolved**; the rest of this file is the record of the frontend gate.

State at the final frontend gate (2026-11-24):

- `apps/api` has **no feature controller yet** (only `src/health`); the module READMEs + Prisma
  schema are the only backend contract. So **every response shape the frontend parses is an
  assumption**, including endpoints whose path is in a README. Each response is parsed by exactly one
  zod schema (named in the group note). When an endpoint lands: fix that schema and the matching mock
  fixture under `apps/<app>/src/app/mock-api/v1/**` together, then run the app's tests.
- Paths below are relative to `/api/v1` unless written in full. Money = integer 만원 (관리비 in 원),
  areas = ㎡, `Decimal` may arrive as string (the schemas coerce), dates ISO / KST days.
- Precedence: where a group note and [`consistency.md`](./consistency.md) disagree (listing card
  fields, dashboard feeds, banner shape, terms schema, favourites, mock ids), **`consistency.md`
  wins** — it is the later cross-group pass.
- Quality gate results (typecheck / lint / tests / production builds) are at the end.

## 6. Cross-cutting contracts

- **Error body** `{ code, message, details?: [{ path, code, message }], requestId }`; validation code
  `VALIDATION_FAILED`; `details[].path` must be the form field (dot path) — every form maps it inline.
  CSRF failures `403 CSRF_FAILED` (the client refreshes the token once and retries). (foundation 5–6)
- **CSRF**: every browser mutation sends `x-csrf-token` = the session's token, kept **in memory**
  (web `lib/api/csrf.ts`): taken from the `csrfToken` of session-creating responses
  (`POST /auth/signup`) and of `GET /auth/csrf` (asked on the first mutation of a page load and after
  `CSRF_FAILED`). The readable `house_csrf` cookie is shared by web and admin, so it is only a last
  resort when `GET /auth/csrf` cannot be reached. (foundation 4, auth README)
- **Cookies**: `house_sid` (user), `house_admin_sid` (admin), httpOnly; the Next middlewares only test
  presence. Admin cookie `maxAge` = absolute TTL while Redis drops at idle TTL → handled client-side by
  `SessionRedirect`. (foundation 7, m-core)
- **Pagination**: `{ items, page, pageSize, total, totalPages }`; cursor feeds `{ items, nextCursor }`.
  Most parsers also accept `{ items }` or a bare array.
- **Listing summary**: one serializer for every card (section 5 / consistency.md). Display name =
  `complexName ?? buildingName ?? title ?? kindLabel`; `title` is the broker's headline, not the name.
- **Content format**: notices, FAQ answers, terms, policies are plain text with light markup (`##`,
  `-`, `1.`, `제1조`, bare URLs). No HTML anywhere; switching to HTML needs a server-side sanitizer and
  both renderers changed together. (w-content, m-content)
- **Path ids** are `encodeURIComponent`-ed by the clients; the API must still validate ids (`idSchema`).
- **Cache tags** used by ISR pages: `listings`, `listing:<id>`, `banners`, `terms` — a backend webhook
  calling `revalidateTag` gives instant updates after edits. (w-listing, w-auth)

## 7. Security and privacy requirements for the API

The UI renders exactly what it receives; these must be enforced server-side.

1. Never send `ho` (호수), owner contact or the 실매물 확인 `note` in public payloads; `floor = null`
   when `floorDisplay = CLASS` (public detail **and** co-broker candidate rows). (w-listing, a-listings)
2. Deal requests before contact consent: masked requester name, location down to 읍면동 / 단지 only —
   never `contactName`, `contactPhone`, `roadAddress`, `addressDetail`, `lat/lng`. (a-inbox 2)
3. Requester names on the dashboard request feed masked by the API (a-agency 6, a-inbox 2); no inquiries for launch (D5).
4. Admin user list and admin search return name / e-mail / phone **already masked**; full values only
   from audit-logged detail reads: `GET /admin/users/:id`, `/admin/agencies/:id`,

## 8. Deployment, environment, third parties

- **nginx** proxies `/api/v1/**` to the API and serves `/media/**` (same origin). For `next/image` on
  `/media/*` set `MEDIA_ORIGIN` to the media origin, or list absolute hosts in `NEXT_PUBLIC_MEDIA_HOSTS`.
- **Production builds** must run with `NEXT_PUBLIC_API_MOCK` unset: then `/mock-api/**` and `/dev/**`
  answer 404 and robots is normal (a mock build answers `Disallow: /`). `NEXT_PUBLIC_SITE_URL` must be
  the public origin (canonicals, sitemap `<loc>`).
- **sitemap.xml** is prerendered at build time; with no API reachable during `next build` the dynamic
  part is empty (warning in the build log) until the first hourly revalidation (`revalidate = 3600`).
  Build with the API reachable, or trigger a revalidation after deploy. Runtime errors keep the last
  complete sitemap. Above ~5,000 ids per resource switch to a sitemap index / `GET /sitemap/ids`.
- **Maintenance**: nginx serves `/maintenance` with `503` while the API is down (snippet in
  [w-content](./w-content.md)); optional `MAINTENANCE_WINDOW`, `MAINTENANCE_MESSAGE`.
- **Naver Maps**: `NEXT_PUBLIC_NAVER_MAP_KEY_ID` + site URL registered in the NCP console; without it
  the static Suncheon map is used. The Naver path has **not been exercised with a real key** — verify
  `/map/apt`, `/map/oneroom`, `/agencies`, the console pin pickers at 1440 and 390 before launch (list
  in [w-map § Behaviour](./w-map.md#behaviour-notes-for-the-integrator)).
- **Kakao postcode** script from `t1.kakaocdn.net` (override `NEXT_PUBLIC_POSTCODE_SCRIPT_URL`; the
  old `t1.daumcdn.net` host retires 2026-11-30).
- **Region codes** env: `NEXT_PUBLIC_REGION_SGG_CODES` (default shared `DEFAULT_SGG_CODE` = `12150`;
  B1 settled by DECISIONS.md D1).
- **CSP**: only `frame-ancestors`, `base-uri`, `form-action`, `object-src` today. A full CSP needs
  nonces and must allow Naver Maps, `t1.kakaocdn.net` (script), `postcode.map.kakao.com` (+
  `postcode.map.daum.net`) frames, `https://www.youtube-nocookie.com` (frame), `https://i.ytimg.com`
  (img), and the Kakao SDK once 카카오 공유 is added (needs a Kakao JS key; the share button is a
  placeholder).
- **Legal review before launch**: agency application / join privacy notices, 직원 관리 legal reminders
  (공인중개사법 제15조, 중개보조원 limit), deal-request consent notices, calculator disclaimers.
